# Fourth and Beers leaderboard

Participants' newspaper for the 2026 Fourth and Beers league: 22 players, Yahoo Pick'em (group 27197) and Survivor (group 22943). The page is the **Fourth and Beers Tribune**, a Chicago Tribune homage in newsprint: banter, insights, fun facts and the prize race. Yahoo already has the detailed standings. The commissioner is Yo. The page is in Mexican Spanish, funny, in the same voice as the league's reglamento.

## Layout

- `index.html`: the page. GitHub Pages serves the repo root from `main`. It fetches `data.json` (or `editions/semana-NN.json` for `?ed=N`) and falls back to a seed copy embedded in the page.
- `data.json` and `editions/`: written ONLY by Publish.gs through the GitHub Contents API. Never edit, regenerate or commit them locally. Always take the remote version. `editions/semana-NN.json` is a full copy of that week's data.json, `editions/index.json` lists the weeks. A week that has moved on is never rewritten.
- `gas/`: the one Apps Script project, bound to the participants workbook (a Sheets button can only call a bound script), managed with clasp. `Publish.js` is `Publish.gs` in the editor, `Code.js` holds the Publicar button (`publishNow`, the Tribune menu, `setupPublishButton`). The project holds only `Publish.js`, `Code.js` and `appsscript.json`. `gas/.clasp.json` carries the workbook id, so it is gitignored (`.clasp.json.example` is the template). `assets/publicar.png` is the button image, served by Pages, drawn by `tools/make_publicar_button.ps1`. The project used to be standalone: its old clasp binding is in git history, and the old project is to be archived. History: the old web app host was undeployed and deleted on 2026-10-01.
- `.github/workflows/tests.yml`: runs the suite on GitHub on pull requests and on pushes that touch code, page, docs or tests, never on the publisher's own data.json and editions commits. It needs no secrets. There is no workflow that pushes to Apps Script: deploys go through `deploy.bat` from the PC (a clasp push from GitHub would need a Google refresh token stored there, which was rejected).
- `assets/og-card.png` (1200x630), `assets/apple-touch-icon.png` (180x180), `assets/favicon-32.png` (32x32): the link preview card, iPhone icon and favicon, referenced by absolute Pages URLs in the static head tags of `index.html` (Open Graph, Twitter, canonical, icons; image URLs carry `?v=1`, bump it on a redraw). `tools/og-card.html` is the template (#card, #icon, #fav, fonts from @fontsource in node_modules) and `tools/make_og_card.js` (run with `make_og_card.bat` or `npm run og-card`, Playwright, needs `npx playwright install chromium` once) redraws the three images. Never run by test.bat or deploy.bat. `test/check_preview.js` checks the tags, URLs and PNG sizes.
- `docs/LEADERBOARD_ARCHITECTURE.html`: architecture doc. Same layout and diagram conventions as the model's `ARCHITECTURE.html` in `..\Model`.
- `docs/mockups/tribune-dia.html`: the approved mockup of the Tribune. Reference for layout, type, colors and copy tone.
- `test/`: Node tests. No live Google or GitHub access. `test/fixtures/week5.json` is the real week 5 data.json in the current schema, `week5-old.json` is the same week in the old schema, `week5-grouppicks.txt` is the real week 5 Yahoo Group Picks table (pipe separated, with the expected Winner row and Yahoo's +/- marks, for assertions only) and `test/picks_fixture.js` turns it into both paste shapes.
- `..\Model`: the separate model repo. Read it for patterns (`deploy.bat`, `test.bat`, `test/`). Never change it from this repo.

## How it runs

- Inputs, participants workbook: `PickEm_Board` (Yahoo weekly performance table pasted at A12, same layout as Picks_Board: instructions in rows 1 to 6, Estado in rows 7 to 10, a colored banner in row 11, headers found by name so a paste at A1 is pushed down, never overwritten), `Tribune` (Semana, Sección, Para, Título, Texto, Publicar checkbox, plus a narrow blank separator column G and the Warnings table in H:J) and `Participantes` (the old Sheet1. Only the columns Call Sign PickEm, Fan of and the optional Apodo, which setup inserts between G and H. Columns are found by header). `Sección` is a dropdown: Portada, Columna, Clasificado, Dato, Edición. Row meaning: Portada is the headline (Título) and deck (Texto), Para optional. Columna is one paragraph of the Portada story in sheet order, Título an optional crosshead. Clasificado is an ad (Título is the ad type, Para is who it is for and shows under the Título, `Q.E.P.D.` or `QEPD` in any case makes it an esquela). Dato is a labeled fact. Edición is at most one per week: Título is a banner under the masthead, Texto replaces the tagline, Para is the theme key (only `muertos` exists). `Apodo` holds comma separated nicknames per participant (Kinky for KinkyKing, Osos for Osos de Grayslake, el Comish for Silverback) so the page can bold them. Emails are never published. `Picks_Board` is Yahoo's Group Picks table (football.fantasysports.yahoo.com/pickem/27197/grouppicks?week=N) pasted at A12, header rows included, under the instructions (rows 1 to 6), the Estado (rows 7 to 10) and a colored banner (row 11). Clear from row 12 down before pasting. A table pasted at A1 by habit is pushed down, never overwritten. In either order with PickEm_Board. There is no week input: the week is the one PickEm_Board week whose scores equal the pasted Points, player by player. None or several matching: nothing is stored, a Spanish warning is listed and the next publish retries. Yahoo's paste carries no win or loss, so the publisher infers each game (F favorite covers, U underdog covers, P push) with a depth-first search so that every pick set's Points equal the confidence of its correct picks. One solution is stored, none or several store the picks with a blank Resultado and a warning, and the pick facts skip that week. `Picks_Log` is the durable store (Semana, Pick Set, Juego, Favorito, Spread, Underdog, Pick, Confianza, Resultado, one row per pick set and game): a re-paste replaces only that week's rows, and no routine ever clears or deletes it (a static test forbids any clear or delete call in Publish.js). An empty cell is a missed pick, a confidence of 0 is a pick with nothing at stake. Playoffs: weeks 19 to 22 have their own paste areas, `Playoffs_Board` (Yahoo's playoff table, header `Pick Set Name`, `Wk 19` to `Wk 22` or `Wk 1` to `Wk 4`, `Total`, everybody starts at zero, paste with formatting so the green winner marks come) and `Playoffs_Picks` (its Group Picks, week=19 to 22), both laid out like the regular tabs (instructions, Estado, banner, paste at A12). Once Playoffs_Board has scores `week` is the playoff week (19 to 22, also the edition and the Tribune Semana), `regularWeek` stays at 18 and data.json gets `playoffs {week, rounds, pickem[], winners}`. Picks_Log keeps weeks 1 to 22. The regular-season weekly $50, prizes, pizzas and carne asada close at week 18, Survivor runs to the Super Bowl and the playoff Pick'em pays first place $700 only (golf rule on ties). Tribune `Semana` takes 19 to 22 or a round name (Wild Card, Divisional, Conferencia, Super Bowl, Playoffs 1 to 4, Ronda 1 to 4). `Premios de la temporada` is the commissioner's prize money table. The scripts never read, write, rename or delete it, and in the participants workbook Publish.js only touches PickEm_Board, Tribune, Participantes, Picks_Board, Picks_Log, Playoffs_Board and Playoffs_Picks. The Estado of the last publish (OK, OK CON AVISOS with the first two warnings, or ERROR, also logged and shown as a toast) sits in rows 8 to 10 of both `Picks_Board` and `PickEm_Board`. Publish rewrites the instructions and the banner if the tab is wiped. Tab order, set by `setupTribuneTab` without ever touching the commissioner tabs: Participantes, Premios de la temporada, Picks_Board, PickEm_Board, Playoffs_Picks, Playoffs_Board, Tribune, Picks_Log. The old `Comentarios`/`Premios` migration has run and its code is gone.
- Input, model workbook: `Field` (Entrant, Strikes). Read only.
- Script properties: `GITHUB_TOKEN`, `GITHUB_REPO`, `SHEET_ID` (participants), `MODEL_SHEET_ID` (model).
- Warnings: every publish checks the current week's checked Tribune rows and lists Spanish warnings in the Tribune tab, one per row from row 2: H is a color swatch, I the text, J the week it was raised (headers `Color`, `Warnings`, `Warning week` in H1:J1). Setup and every publish insert the separator G if the table still starts in G, and strip the checkboxes and tints Sheets copies into it from Publicar. The rows a warning points at get the same color in A:F, striped when several warnings share a row. It warns when the last place is named in more than one row or Columna paragraph, was also named last week, when Columna has no Portada, when there is more than one Edición or an unknown tema, or when a Clasificado has a blank Para (it is still published). This week's warnings are recomputed each publish, those of the previous 3 weeks stay below as a rolling log, older ones roll off. It never blocks a publish and never edits text. Only the palette colors are ever cleared.
- Publicar button: image at K1 of the Tribune tab (and a Tribune menu) runs `publishNow` (Code.js), which calls `publishManual()` and shows a popup. `publishLeaderboard()` and `publishManual()` return `{status: published | no_changes | busy | error, week, commitSha, updatedAt, message}`. `publishLeaderboard()` still throws on failure and waits up to 60 seconds for the script lock, `publishManual()` never throws and gives up on the lock after 5 seconds (busy). K1 is right of everything the code uses on the Tribune tab (A:F, the G separator, H:J, whose widths `WARN_WIDTHS` keeps narrow): never move the button onto those columns, never insert rows or columns for it.
- Triggers: installable onEdit on the participants workbook (PickEm_Board, Picks_Board and Tribune) and a daily 7am `publishLeaderboard`. Runs are serialized with a script lock.
- `publishLeaderboard` reads the live data.json first (for `survivorOut` and the sha), builds a new one, then writes the week's edition, the edition index and data.json, in that order. Each file is committed only when something other than `updated` changed. A missing Tribune tab publishes an empty `tribune`.
- data.json fields: `season`, `week`, `weeks`, `updated`, `prizes {regular[], survivor[], playoffs[], weekly, weeks}`, `pickem[] {name, weeks[], total, dropped, droppedWeek?}`, `winners [[name]]` (one list per week), `strikes {name: n}`, `survivorOut[] {name, week}` (a new elimination is stamped with the NFL week of the calendar as Yahoo counts it: week 1 opens Wed 2026-09-09, every later week runs Thursday 00:00 to Wednesday in America/Chicago, so a Tuesday or Wednesday update belongs to the week just played, capped at 18; in the playoffs the edition week; v3.2.1 also ran a one-time data fix that sets X-Men Let's go Boys to week 5 and King of The North and Niners to week 6, guarded by the Script property `SURVIVOR_WEEK_FIX_V3_2_1`, to be removed from Publish.js after that publish), `fans {name: {nfl, ncaa} | {random, other}}`, `apodos {name: [alias]}`, `regularWeek` (only in the playoffs), `playoffs {week, rounds, pickem[] {name, weeks[], total}, winners [[name]]}` (only once Playoffs_Board has scores), `picks {week: {g: [[fav, spread, dog, res]], p: {callSign: [[team, conf] | null]}}}` (one key per stored week, res F, U, P or null, rebuilt from Picks_Log on every publish), `tribune {portada: {titulo, texto, para} | null, columna[] {titulo, para, texto}, clasificados[] {titulo, para, texto}, datos[] {titulo, para, texto}, edicion: {titulo, texto, tema} | null}`. Yahoo is canon for the weekly winner and the dropped week, as for Total and Dropped: in the pasted PickEm_Board a green font marks the week's winner (Yahoo already applied its tiebreakers) and a red font the dropped week. The publisher reads the cell font colors (so paste with formatting, not as plain text) into `winners` and `droppedWeek`. Without colors the previous data.json's marks stand while that week's scores are unchanged, a single top score wins by itself, and an unmarked tie is a warning and splits on the page. Never recompute a winner or a dropped week in code or in comments, read these fields. The prize amounts live in one `PRIZES` constant in Publish.js.
- `SURVIVOR_TO_PICKEM` in Publish.js maps Survivor call signs to Pick'em call signs. Apostrophes are normalized (Yahoo uses curly ones).
- The page still reads the old schema (pays, weeklyPrize, comments, awards) until the first publish after the 3.0 deploy, then ignores those fields. A data.json without apodos, edicion, picks or Columna titulo renders as is.
- Names: one resolver, the same code block in `index.html` and `Publish.js` between `// BEGIN NAMES` and `// END NAMES` (a test fails if they differ). Call signs plus apodos, case-insensitive, curly and straight apostrophes equal, whole words, longest match first. The page bolds mentions with `<b class="nombre">` and gives the selected reader `.tuyo`. Sheet text is always escaped first.
- Name panel: three things, the Subidas y bajadas chart, "Tus picks" (up to 4 short lines from weeks with results: top 3 confidence hits with an arrow for the last 3 weeks only when it differs from the season by 10 points or more, favorites against underdogs, the team that paid and the one that cost most, your own team, hidden for Jorge_B and the Suiza players) and the Survivor strikes. Missed picks and confidence 0 picks are left out. No picks data or no week with results hides Tus picks and the panel looks as before. The panel stays exempt from the last-place budget.
- Datos que nadie pidió owns the oddities and league-wide comparisons. Every other data point has one owner: Premios, pizzas y carne asada own prize money, weekly winners, money per fan base and its note, who pays the pizzas and the gap, and the carne asada. The name panel owns the player's rank chart, their 4 Tus picks lines and their strikes. The Tribune rows own whatever they say. The engine enforces it: `aficiones` and `sotano` are retired from Datos, a fact about one player never prints a number that player's Tus picks lines show, and every fact has a `huella` {nombres, equipos, numeros} (everything its templates can print). A fact is dropped when a printed Portada, Columna, Clasificado or Dato row names one of its players or teams and repeats one of its numbers (its alternates, 3 at most, or the next candidate take the slot, and `T.plan(M).pk.dropped` says why).
- Fact rules (deterministic, `{rule, valor, titulo, texto, estilo, score, sujetos, huella}`, 6 facts, about 120 characters). A rule that ran in last week's archived edition goes to the back of the line. No archive for last week means nothing is held out. Each rule has a `desde` week (the first edition it was live, 5 for all of them). The page fetches `editions/semana-(week-1).json` at boot for this. 1 to 12 are the older ones: rebote, arriba, fotocopia, disco, racha, record, remontada, siempre, peor, survivor (aficiones and sotano retired). Pick-level, keeping the 3.2 numbering: 16 lealtad (the fan base whose fans together won or lost the most points picking for or against their own team, 2 or more fans, Pick'em only, not Jorge_B or Suiza, never an average), 17 mismo equipo, 18 costalazo, 19 llanero solitario, 20 borregada, 21 empate, 22 se le olvidó, 23 racha de picks (consecutive correct picks only), 24 amante de los perros (named with the gap to the next player, never the share), 25 contra la corriente. New: 26 jugamos como nunca (the biggest gap between rank by hits and rank by points), 27 el orden sí altera el producto (same team in every game, largest point gap), 28 polos opuestos (fewest games agreed), 29 cría cuervos (the team whose losing picks cost the league most confidence), 30 el acomodador (points against the most the same hits could have scored in the top confidence slots). 13 to 15 are unassigned. Rules 26 to 30 score by rarity, `50 + 45 × percentile` among the same measure for every player-week so far, and are not produced below the 90th percentile (27 also passes at a 10 point gap). A rule may carry up to 3 alternates, tried when its leader is skipped. The playoffs add `playoffs`, `poronda` and `posube`.
- Humor styles: templates are `{s, t}` with styles `carrilla`, `albur`, `refran`, `nunca`, `nimodo`, `apodo`, `calaverita`. Every group has 3 or more templates in 3 or more styles, one an albur where the data allows. After the 6 facts are chosen, in score order, each takes the first template from a week-rotated offset whose style has room: carrilla 2, albur 2, every other style 1 (a fact keeps its first template if nothing fits). `apodo` needs a named player with an apodo. `calaverita` only with the muertos theme, up to 2 facts, 4 lines joined with " / ", lines 2 and 4 must share a consonant rhyme on fixed words (never on a placeholder), lines 1 and 3 rhyme too when they end in fixed words, no rhymes on two -ar infinitives, about 8 syllables a line, max 34 characters after fill. Albures on the page are spicy (adults only), with the limits in this change: clear Mexican doble sentido and sexual innuendo about the picks, the numbers and the teams, no explicit vocabulary, no slurs, no orientation as an insult, nothing about anyone's real life, partner or family. Never on Andrea's Picks or Juan1768. Each rendered fact carries `data-estilo`, no visible label.
- Last-place rule: the last place (every player tied for last, golf rule) is roasted at most once per edition. Priority: the Portada story (never cut), the first Clasificado, Datos, then the automatic facts, which carry `sujetos`. Items over budget are not rendered. Pizzas, prize tiles and the name panel are exempt.
- Themes: `THEMES` in index.html and `THEMES_KNOWN` in Publish.js, plus an `html[data-tema]` CSS block that only remaps tokens. `muertos` swaps the accent for a marigold. Chart and prize colors never change.

## Rules

- Versioning: every file carries `v major.minor.bug c major.minor.bug`. v tracks functionality, c tracks content. `index.html` (footer), `Publish.js` (header comment) and the doc (masthead and footer) version independently. Bump on every change.
- Deploy only with `deploy.bat` (it pushes `gas/` and stops if `gas/.clasp.json` is missing). Never run `clasp push`, `git push` or `git commit` by hand.
- `test.bat` must pass before any deploy.
- When a tab, data.json field, flow function, trigger or page section is added, renamed or retired, update the architecture doc in the same change and bump its version.
- Page: one self-contained HTML file, vanilla JS, no build step, mobile first. Newsprint, light only: `color-scheme: only light` plus explicit backgrounds so iOS dark mode cannot invert it. Every color is a token in the `:root` block and nowhere else. Every number and sentence is computed from data.json in the browser. The fact engine is deterministic rules, never a model call.
- Copy: Spanish page text in the reglamento's voice. Plain verbs, dry understatement, no em dashes, no semicolons chaining clauses. Roast the picks and the teams, never people's personal lives. Jorge_B picks at random and only teases the die-hard fans. Fact sentences never mention the commissioner's model or Jorge_B's random picking, and run about 120 characters at most.
- Penalties, per the reglamento: last place in the regular-season Pick'em pays the Super Bowl party pizzas for everyone, families included. The first Survivor elimination organizes the carne asada for all participants. Ties split the bill. Prize ties follow the golf rule.
- Privacy: this repo is public. Only call signs, points, strikes, fan teams, the reglamento's prize amounts and published Tribune rows belong here. Never put emails, real names, payment details, workbook IDs or tokens in code, tests, docs or commit messages.
- Visit counting: GoatCounter, site code `fourthandbeers` (cookie-less, no personal data), a standard async `count.js` at the end of `index.html` with `no_onload` so the page counts itself once per load with `goatcounter.count({path:"/semana-N"})`, N the data.json week, so views group by edition and query strings and hashes never count. It runs after the render, never blocks it and does nothing if the script is blocked. The commissioner excludes their own browsers by opening the page once with `#toggle-goatcounter` (GoatCounter's documented switch, stored in that browser's localStorage). Dashboard: fourthandbeers.goatcounter.com.
- Yahoo is behind the commissioner's login. No scraping, no stored Yahoo credentials.
- Weekly routine, after Monday Night Football: paste the Yahoo weekly performance table into PickEm_Board and the Group Picks table into Picks_Board, in any order. Check the Warnings table in the Tribune tab for Picks_Board lines.
- Weekly Tribune batch, when asked: read the current data.json (its `winners` and `droppedWeek` are Yahoo's, never name another winner or dropped week) and the last four editions, then draft 1 Portada (headline and deck), 5 to 6 Columna paragraphs that form one story, 4 to 6 Clasificado rows and optional Dato and Edición rows, as a CSV file (Semana, Sección, Para, Título, Texto) ready to import. Last place is named in one row at most. Para is an exact Pick'em call sign, a comma separated list of them, or Todos. Same voice rules as above. Do not repeat what the fact engine already prints.
