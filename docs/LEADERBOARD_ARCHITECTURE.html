How this document stays current

Unlike the model's ARCHITECTURE.html, nothing generates this page yet. The leaderboard files live in a standalone Apps Script project and a GitHub repo, not in the clasp repo, so there is no docs.bat and no R10 check behind it. It follows the same layout and the same rules by hand.

  1. Change the code the usual way: share the file with Claude, get it back.
  2. If the change adds, renames or retires a tab, a data.json field, a function in the flow table, a trigger or a page section, Claude updates this page in the same change and bumps its version.
  3. Deploy the code (see Deploy steps). Keep this file next to the model's docs.
  4. When the leaderboard moves into git, this page becomes a generator output like the model's. That is on the known gaps list.

Data flow and storage

Each row is one flow: where the data comes from, what moves it, where it lands. Everything on the right of the first five rows is one file, data.json, built in memory and committed once.

What the rows cannot show

  • survivorOut needs the previous data.json. readCurrent_ fetches it before anything is built, and the same read supplies the sha the GitHub API needs to update the file.
  • onEdit only fires for edits made by a person. When the model writes Field strikes by script, nothing fires until the daily 7am run.
  • A run whose numbers match the live file commits nothing. The updated timestamp alone never creates a commit.
  • The page tries data.json first and falls back to the seed copy embedded in index.html, which is why a local file or the Claude preview still renders.

Known gaps

Yahoo stays manualThe leaderboards sit behind the commissioner's login. A script holding the Yahoo password would be fragile and a risk, so the weekly paste stays. Claude can do it through Chrome on request.
Strikes lag up to a dayField changes written by the model's scripts do not fire onEdit. The page picks them up at the next 7am run, or at the next board paste.
No repo, no tests, no generatorPublish.gs and index.html are not in git. They were tested with mocks in Claude's sandbox, not in a suite you can rerun. This page is kept by hand.
Token expires after the Super BowlThe fine-grained token was set to expire mid-February 2027. Publishing stops with a 401 until it is replaced.
Name map lives in codeA new or renamed Survivor call sign needs a code change to SURVIVOR_TO_PICKEM. The run log names the unmatched entry.
Public repoFree GitHub Pages needs it. The repo holds call signs, points, strikes, fan teams and published comments. No names, emails or money.

Deploy steps

Every file carries v major.minor.bug c major.minor.bug, v for functionality, c for content. Unlike the model's six build scripts, these files version independently.

#ChangeSteps
1index.htmlBump the footer version. Run deploy.bat. It commits and pushes, GitHub Pages is live in a minute or two.
2Publish.jsBump the header version. Run deploy.bat, which clasp pushes it from gas. Then run publishLeaderboard once from the editor and read the log.
3TriggersRerun installTriggers only when a watched tab or the schedule changes.
4New tabRun its setup helper once, like setupComentarios.
5This documentUpdate the views and tables, bump the version in the masthead and the footer.
6data.jsonNever by hand. The next run overwrites it.
