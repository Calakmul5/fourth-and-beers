How this document stays current

Unlike the model's ARCHITECTURE.html, nothing generates this page yet. The leaderboard files live in a standalone Apps Script project and a GitHub repo, not in the clasp repo, so there is no docs.bat and no R10 check behind it. It follows the same layout and the same rules by hand.

  1. Change the code the usual way: share the file with Claude, get it back.
  2. If the change adds, renames or retires a tab, a data.json field, a function in the flow table, a trigger or a page section, Claude updates this page in the same change and bumps its version.
  3. Deploy the code (see Deploy steps). Keep this file next to the model's docs.
  4. When the leaderboard moves into git, this page becomes a generator output like the model's. That is on the known gaps list.

Layered view

The whole leaderboard in one ArchiMate view: what the commissioner does, the application pieces that do it, and where they run. Elements take the ArchiMate layer colours. Services are drawn as pills and data objects as square boxes. Hover or long-press a box for its description.

Data flow and storage

Each row is one flow: where the data comes from, what moves it, where it lands. Everything on the right of the first five rows is one file, data.json, built in memory and committed once.

What the rows cannot show

  • survivorOut needs the previous data.json. readFile_ fetches it before anything is built, and the same read supplies the sha the GitHub API needs to update the file.
  • Each publish writes three files in a fixed order: editions/semana-NN.json for the current week, editions/index.json, then data.json. Each is committed only when something other than the timestamp changed, and a week that has moved on is never rewritten.
  • Every publish ends with a status message: a log line, a toast in the workbook and rows 8 to 10 of Picks_Board and PickEm_Board (OK, OK CON AVISOS with the first two warnings on their own rows, or ERROR with the message, after which the error is raised as before).
  • Picks: syncPicks_ reads Picks_Board, finds the one PickEm_Board week whose scores equal the pasted Points (none or several: nothing is stored and a warning is listed), then infers each game result with a depth-first search so that every pick set's Points equal the confidence of its correct picks. One solution is stored, none or several store the picks with a blank Resultado and a warning. The week goes to Picks_Log (only that week's rows are replaced) and data.json picks is rebuilt from Picks_Log on every publish.
  • A missing Tribune tab publishes an empty tribune and the page uses its fallbacks, so the first run after a deploy cannot fail on it.
  • onEdit only fires for edits made by a person. When the model writes Field strikes by script, nothing fires until the daily 7am run.
  • A run whose numbers match the live file commits nothing. The updated timestamp alone never creates a commit.
  • The page tries data.json first and falls back to the seed copy embedded in index.html, which is why a local file or the Claude preview still renders.

data.json contract

Written only by Publish.gs, read only by index.html. Adding a field is safe: the page ignores what it does not know. The page also still reads the old schema (pays, weeklyPrize, comments, awards) until the first publish after the 3.0 deploy, and then ignores those fields. A data.json from before 3.1 (no apodos, no edicion, no titulo in columna) or before 3.2 (no picks) renders as is. Each editions/semana-NN.json has exactly this shape.

Page sections

Every color is a token in the :root block. Every number and sentence is computed from data.json in the browser. There are no model calls.

Name panel

A bottom sheet that opens when a name is picked, with a mini masthead, a close button, the call sign and one line (rank, points, Survivor lives). Inside it three blocks: Subidas y bajadas, the bump chart with both toggles and the biggest climber and drop (selected player in red, climber green, drop burnt orange), Tus picks, and the Survivor strikes summary with the selected card outlined in red. Tapping a line follows that player. Tus picks sits between the chart and the strikes: at most four short lines from the weeks with results (hits on your top 3 confidence picks with an arrow only when the last 3 weeks and the season differ by 10 points or more, favorites against underdogs, the team that paid and the one that cost most, and your own team, hidden for Jorge_B and the Suiza players). Missed picks and confidence 0 picks are left out. Without picks data or a week with results the block is hidden and the panel looks as before.

Playoff phase

Once data.json carries a playoffs block the edition is a playoff edition: the dateline says Edición N, playoffs, the Portada falls back to the playoff leader (Arrancan los playoffs, Playoffs: ronda r de 4, Se acabó la temporada), the Quiniela de playoffs card lists the top five with Yahoo's round winners and the pill reads en juego or final, and the regular-season facts are replaced by the playoff rules (playoffs, poronda, posube) plus Survivor and the pick rules, which read the playoff week. The regular league stays at its last week, so the weekly tiles, regular money, pizzas and carne asada are unchanged. Round 4 pays the first place $700 (golf rule on ties). Tribune rows use Semana 19 to 22 or a round name.

Archive

?ed=N loads editions/semana-NN.json and renders the same page, frozen, under a banner "Edición N, archivo" with a link back. A missing file falls back to the current edition. The edition applies its own theme, and the current edition stays plain.

Portada story

The Columna rows are the body of the Portada, in sheet order. Drop cap on the first paragraph only. A Título on a Columna row is a crosshead above its paragraph (Libre Franklin small caps in the accent color). A newline or " / " inside a Columna Texto is a line break: that paragraph is verse, left-aligned, with no drop cap. The last paragraph ends with ■. Without a Portada row the automatic headline and deck stand in and the Columna rows still form the body. Without Columna rows the Portada is headline and deck only.

Names

One resolver, the same code block in index.html and Publish.js (a test fails if they differ): call signs plus apodos, case-insensitive, curly and straight apostrophes equal, whole words only, longest match first (Manolito's winning picks before Manolito). In the deck, story, crossheads, clasificados, datos and the Edición banner every mention is wrapped in <b class="nombre">. The headline is not wrapped. Sheet text is escaped before wrapping, so nothing from the sheet becomes markup.

Esquelas

A Clasificado whose Título is Q.E.P.D. in any spelling (QEPD, q.e.p.d) renders as an esquela: 2px ink frame, centered, a small cross above the Título, Para in Playfair as the name. It works every week.

Special editions

A checked Edición row (one per week) adds the banner and tagline. Para is the theme key. The themes live in one lookup, THEMES in index.html, plus an html[data-tema] block that only remaps tokens. Only muertos exists: the accent becomes a dark marigold that passes 4.5:1 on the paper, and a papel picado strip made of CSS gradients shows under the masthead. Chart and prize colors stay as they are. An unknown tema is ignored.

Last-place rule

The last place is roasted at most once per edition. Everyone tied for last (golf rule) is protected. Order of priority: the Portada story (headline, deck and paragraphs count as one item and are never cut), then the first Clasificado in sheet order, then Datos, then the automatic facts. A row naming a protected player once the slot is used is not rendered. A Para that names the player counts. Each automatic fact carries sujetos, the players it names, and the selector skips a fact about a protected player once the slot is spent, La cifra included, so the next candidate takes its place. Exempt: the Pizzas card, the prize tiles and the name panel. The publisher's Warnings table lists the same cases while the rows are being written.

The engine enforces it. The aficiones and sótano rules are retired from Datos. A fact about one player never prints a number that player's Tus picks lines show. Every fact has a huella, the players, teams and numbers it can print across all its templates. A fact is dropped, and its alternates (3 at most) or the next candidate take the slot, when a printed hand-written row (Portada, Columna, Clasificado or Dato) names one of its players or teams and repeats one of its numbers as a whole token. La cifra goes through the same check. T.plan(M).pk.dropped lists each drop as {rule, por}, for example the Fotocopia fact against the Fotocopia Clasificado with 281.

Humor styles

Templates are {s, t} objects. Styles: carrilla, albur, refran (a twisted refrán), nunca (jugamos como nunca, perdimos como siempre), nimodo, apodo and calaverita. Every fact group has at least 3 templates in at least 3 styles, one an albur wherever the data allows it. After the 6 facts are chosen, in score order, each takes the first template from a week-rotated offset whose style still has room: carrilla 2, albur 2, every other style 1, and a fact keeps its first template when nothing fits. Apodo needs a named player with an apodo and uses it. Calaverita only in the muertos edition: up to 2 facts, 4 lines joined with " / ", lines 2 and 4 rhyme, every line up to 34 characters. An albur never goes on a fact that names Andrea's Picks or Juan1768. Each rendered fact carries a data-estilo attribute and no visible label. Albur is spicy and adults only: clear doble sentido on the picks, the numbers and the teams, no explicit vocabulary, no slurs, nothing about anyone's real life.

Fact engine

Deterministic rules over data.json. Each rule returns one fact (rule, value, label, sentence, score, estilo, huella) or nothing, with styled Spanish templates that rotate by week. Rules 26 to 30 score by rarity, 50 plus 45 times the percentile of the value among the same measure for every player-week so far, and are not produced below the 90th percentile (rule 27 also passes with a gap of 10 points or more, because identical picks are common). The 6 highest scores are picked, a rule that ran in last week's edition goes to the back when another candidate exists, and the highest-scoring numeric fact becomes La cifra de la semana. Last week's edition is found by running the same engine on this table cut back one week.

The pick-level rules (numbered 16 to 30 in CLAUDE.md) read data.json picks. Only weeks whose results were inferred count. Confidence 0 picks count for loyalty and herd facts, never for points. Week-only rules look at the current week.

Initials

First letter of the first two meaningful words. Words split on spaces, underscores, hyphens and camelCase, a trailing 's is dropped, and of, the, de, la, el, is, our, go, que, lo, let's and winning are skipped. A one-word name takes its first two letters. A collision gets a third letter, so all 22 are unique.

Known gaps

Yahoo stays manualThe leaderboards sit behind the commissioner's login. A script holding the Yahoo password would be fragile and a risk, so the weekly paste stays. Claude can do it through Chrome on request.
Strikes lag up to a dayField changes written by the model's scripts do not fire onEdit. The page picks them up at the next 7am run, or at the next board paste.
Tests cannot reach Google or GitHubThe suite runs on mocks. Triggers and the live GitHub write can only be proven by running them in the editor. This page is still kept by hand.
Editions start at week 5Only the current week was ever published, so ?ed=1 to ?ed=4 do not exist and fall back to the current edition.
Results are inferredYahoo's paste carries no win or loss. The publisher solves for the results that make every pick set's Points add up. When no combination fits, or several do (a game nobody took the underdog in cannot tell U from P), the week is stored with blank results, a warning is listed and the pick facts skip that week.
Picks need PickEm_Board firstThe week is found by matching the pasted Points against PickEm_Board, so paste the weekly table too. Until it matches, nothing is stored and a warning is listed. The next publish retries.
Last week is approximatedThe no-repeat rule runs the engine on this table cut back one week. Strikes before this week are approximated from survivorOut.
Token expires after the Super BowlThe fine-grained token was set to expire mid-February 2027. Publishing stops with a 401 until it is replaced.
Warnings are adviceThey are recomputed on every publish and tint rows, but never block a publish and never edit text. Only the current week and last week's checked rows are checked. Warnings from the previous three weeks stay listed below as a log, then roll off. The last-place budget on the page is the enforcement.
Themes need two editsA new theme is a key in THEMES_KNOWN (Publish.js) and in THEMES (index.html) plus one CSS block.
Name map lives in codeA new or renamed Survivor call sign needs a code change to SURVIVOR_TO_PICKEM. The run log names the unmatched entry.
Public repoFree GitHub Pages needs it. The repo holds call signs, points, strikes, fan teams and published comments. No names, emails or payment details. The prize amounts are the reglamento's and are public.
